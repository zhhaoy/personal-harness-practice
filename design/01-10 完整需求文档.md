# 功能需求
## 01-核心循环（01-agent_loop.py）
**目的**：构建*核心循环*。
期望做到这个循环是对LLM的唯一接口。应摒弃通过大量代码搭建框架来约束LLM的思维，而把注意力完全聚焦在为LLM提供资源（工具）上！**当LLM开始调用资源（工具），循环开始；当LLM不再需要使用资源（工具），退出循环。**

第一步：循环构建
**用户需求注入**：初始化messages，确保用户需求正确注入。
**循环退出条件**：当且仅当模型不再需要继续调用任何工具时，立即退出循环。
**单次循环**：当执行单次循环，即调用一次大模型时，需要告知大模型messages、tools、超时设置等，并记录大模型输出。

第二步：返回结果
**结果结构**：返回的内容中需要包含中间工具调用情况、错误情况（如有）、实际结果。

第三步：**提供验证问题**：
1. `创建一个名为 hello.py 的文件，该文件打印 "Hello, World!"`
2. `列出本目录下所有Python文件`
3. `创建目录 test_output 并在里面创建3个Python文件`

## 03-待处理列表机制（03-agent_loop.py）
**目的**：构建*ToDo工具*。
调用ToDo工具创建、更新待处理列表，直至所有事项完成。
预防Agent只见树木不见森林、捡了芝麻丢了西瓜，提供一个**工具**，以让Agent先规划、再执行。

第一步：ToDo工具初次调用时机
**规划先行**：要求Agent任何时候若是判断任务复杂，则需调用ToDo工具，初次调用会创建*ToDo列表*。

第二步：ToDo列表更新时机
**周期提醒**：
1）每3轮Agent回复，在下一轮需额外插入提示以告知Agent去调用ToDo工具、更新ToDo列表。
2）某一步执行结束，调用ToDo工具、更新ToDo列表。

第三步：ToDo列表完成时机
**循环结束标志**：ToDo列表所有步骤完成。退出循环前如有未完成步骤，应调用ToDo工具以继续执行未完成步骤。

第四步：**提供验证问题**
1. `重构 hello.py 文件：添加类型注解、文档字符串和 main 保护块。`
2. `创建一个 Python 包，包含 __init__.py、utils.py 和 tests/test_utils.py。`
3. `检查所有 Python 文件并修复任何风格问题。`

## 06-上下文压缩机制（06-agent_loop.py）
**目的**：避免上下文爆炸，分三个级别对上下文进行压缩。

第一步：占位符替换
**微压缩（micro_compact）**：自动/静默执行，将最近N轮（如3轮）的tool_result替换为简短占位符。只替代较长结果，保留最近的结果细节，从而立即减少上下文冗余。

第二步：对话保存 + Agent总结 + 替换上下文
**自动压缩**：当估算词元数超过阈值（如50000）时触发自动对话转录，将完整对话保存到本地.transcripts/目录下，以防止数据丢失。同时让Agent对当前对话（如截取前80000字符）生成摘要，以此替换所有历史消息，只保留一个包含标记的用户消息。

第三步：上下文压缩工具
**手动压缩**：提供*compact工具*，Agent在需要时主动调用，效果与自动压缩一样。

第四步：**提供验证问题**
1. `逐个读取 agents/ 目录中的每个 Python 文件`（观察微压缩如何替换旧的结果）
2. `持续读取文件，直到自动压缩被触发`
3. `使用 compact 工具手动压缩对话`

## 07-后台任务处理机制（07-agent_loop.py）
**目的**：构建*background_run工具*。
调用background_run工具，在一个耗时任务正在执行期间（比如安装某个库），可以将其置于后台，而后并行处理其它请求（比如生成配置文件），避免LLM闲置。

第一步：启动后台任务
**守护进程**：当执行一个可能很慢的命令（如库安装），启动一个守护线程（拥有唯一task_id），并立即返回结果给Agent，以使得它能继续处理其它请求。

第二步：守护进程结果通知
**通知队列**：守护进程执行结束，结果置于线程安全的通知队列（notification queue），该队列内容会在每次调用LLM前作为用户消息注入对话。

第三步：**提供验证问题**
1. `在后台运行 “sleep 5 && echo done”，然后在它运行期间创建一个文件。`
2. `启动 3 个后台任务：“sleep 2”、“sleep 4”、“sleep 6”，并检查它们的状态。`
3. `在后台运行 pytest，同时继续处理其他事情。`

## 08-团队协作机制（08-agent_loop.py）
**目的**：队员创建、队内通信工具*spawn_teammate、send_message、read_inbox、broadcast*等。
调用相应工具，Leader Agent（初始Agent）可以创建队员、给特定队员发送信息、给所有队员广播信息、接收信息等。
先前的子代理机制，不能将角色持久化，一次对话结束后，子代理生命终止。而队员创建后，可以持久存在。

第一步：创建持久化队员
**队员创建**：生成.team文件夹，团队名册保存在文件夹内的config.json中，这样Agent重启后，队员也能保留。每位队员是独立线程，有自己工具、上下文、系统提示语。

第二步：队员生命周期管理
**生命周期管理**：自带“idle”、“working”和“shutdown”属性，按照工作状态进行切换管理。

第三步：队内通信管理
**基于文件的异步邮箱系统协作机制**：每个队员有自己的文件（如.team/inbox/xxx.jsonl），xxx队员在下一轮循环中将自己inbox中的jsonl内容注入上下文（Leader可以调用工具向xxx.jsonl追加消息）。

第四步：**提供验证问题**
1. `生成队友 alice（编码者）和 bob（测试者）。让 alice 给 bob 发送一条消息。`
2. `向所有队友广播“状态更新：第一阶段已完成”。`
3. `检查主控团队的收件箱中是否有任何消息。`
4. 输入 /team 查看带有状态的团队名册。
5. 输入 /inbox 手动检查主控团队的收件箱。

## 09-自主智能体机制（09-agent_loop.py）
**目的**：让队友轮询任务看板，主动领取未被分配的任务。任务被固化为文件，并能对任务的各种属性进行管理（如领取人员、完成状态等）。

第一步：任务创建
**持久化任务管理**：在.task文件夹内生成任务文件，包含status：pending / in-progress / done / blocked、owner、subject等。

第二步：任务领取
**任务看板轮询机制**：队友Agent每隔一段时间（如5s）轮询.task文件夹内任务，领取未被指派任务（通过scan_unclaimed_tasks()检索），并维护自身状态（如idle->  working）及维护任务状态（如unassign->assigned）。

第三步：任务完成通知
邮箱消息通知Leader Agent任务完成情况。

第四步：**提供验证问题**
1. `在任务板上创建 3 个任务，然后生成队友 alice 和 bob。观察他们如何自动认领任务。`
2. `生成一个编码队友，让它自行从任务板中找到工作。`
3. `创建带有依赖关系的任务。观察队友如何遵守被阻塞的顺序。`
4. 输入 /tasks 查看带有认领者的任务板。
5. 输入 /team 监控哪些队友正在工作，哪些处于空闲状态。

## 10-任务隔离机制（10-agent_loop.py）
**目的**：将“任务逻辑单元”与“物理执行环境”解耦，每个任务获得独立的分支、工作目录和 Git 历史
创建工具用以为每个任务生成独立（物理隔离）的工作区域，以防所有任务都运行在同一个共享目录下，可能会产生严重冲突。任务看板追踪做什么，任务隔离机制解决在哪里做。

第一步：创建 Worktree 并绑定任务
**Git Worktree（工作树）机制**：为每个任务创建独立的目录和独立的Git分支，在.worktrees/目录下，通过task ID与特定./task/目录下的task关联。（所以要求工作区同时也是Git库）

第二步：在隔离环境中执行命令
Agent 在执行 shell 命令时，需要指定 cwd 为该 worktree 的路径，而不是项目根目录；所有文件修改（编辑、创建、删除）都发生在该 worktree 目录内，其他 worktree 不受影响。

第三步：完成与清理
完成任务后，有两种选择：
1. 保留 worktree：调用 worktree_keep(name)，仅标记 worktree 为保留状态，不移除目录。可能用于后续审查或合并。
2. 移除 worktree 并完成任务：调用 worktree_remove(name, complete_task=True)。

第四步：**提供验证问题**
1. `为后端认证和前端登录页面创建任务，然后列出所有任务。`
2. `为任务 1 创建工作树 “auth-refactor”，然后将任务 2 绑定到新的工作树 “ui-login”。`
3. `在工作树 “auth-refactor” 中运行 “git status --short”。`
4. `保留工作树 “ui-login”，然后列出所有工作树并查看事件记录。`
5. `移除工作树 “auth-refactor” 并设置 complete_task=true，然后列出任务、工作树和事件。`
